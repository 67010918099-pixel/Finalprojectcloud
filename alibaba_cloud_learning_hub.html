1. IaaS — Infrastructure as a Service

โครงสร้างพื้นฐานในรูปแบบบริการ

ความหมายของ IaaS

Infrastructure as a Service (IaaS) หรือ โครงสร้างพื้นฐานในรูปแบบบริการ เป็นรูปแบบการให้บริการคลาวด์คอมพิวติ้งที่ผู้ให้บริการจัดเตรียมทรัพยากรด้านเทคโนโลยีสารสนเทศผ่านอินเทอร์เน็ต เช่น เซิร์ฟเวอร์เสมือน พื้นที่จัดเก็บข้อมูล ระบบเครือข่าย และทรัพยากรประมวลผล ผู้ใช้งานสามารถเลือกขนาดและกำหนดค่าทรัพยากรให้เหมาะสมกับลักษณะงาน โดยไม่จำเป็นต้องซื้อ ติดตั้ง และดูแลเครื่องเซิร์ฟเวอร์จริงทั้งหมดด้วยตนเอง

IaaS ช่วยให้องค์กรเริ่มต้นใช้งานระบบสารสนเทศได้รวดเร็วขึ้น ลดการลงทุนในฮาร์ดแวร์ และปรับเพิ่มหรือลดทรัพยากรได้ตามปริมาณงาน อย่างไรก็ตาม ผู้ใช้ยังต้องดูแลส่วนที่อยู่ภายใต้ความรับผิดชอบของตน เช่น ระบบปฏิบัติการ การติดตั้งซอฟต์แวร์ และการรักษาความปลอดภัยของแอปพลิเคชัน

ภาพประกอบ Alibaba Cloud

IaaS ของ Alibaba Cloud: Elastic Compute Service (ECS)

Elastic Compute Service (ECS) เป็นบริการเซิร์ฟเวอร์เสมือนบนคลาวด์ของ Alibaba Cloud ที่ช่วยให้ผู้ใช้สร้างและจัดการเครื่องประมวลผลเสมือนได้ตามต้องการ สามารถเลือกรูปแบบเครื่อง จำนวน CPU หน่วยความจำ และการตั้งค่าที่เหมาะสมกับแอปพลิเคชัน ECS สอดคล้องกับ IaaS โดยตรง เพราะผู้ใช้ควบคุมการตั้งค่าระบบปฏิบัติการและซอฟต์แวร์ที่ติดตั้งบนอินสแตนซ์ได้ ขณะที่ Alibaba Cloud จัดเตรียมโครงสร้างพื้นฐานทางกายภาพและระบบเสมือนให้บริการ

บริการประมวลผลของ Alibaba Cloud ยังมีตัวเลือกอื่นตามประเภทของงาน เช่น ระบบประมวลผลประสิทธิภาพสูงและเครื่องที่ออกแบบมาเพื่อรองรับงานเฉพาะทาง ผู้ใช้ควรเลือกทรัพยากรจากความต้องการด้านประสิทธิภาพ งบประมาณ และรูปแบบการใช้งานเป็นหลัก

✓ ข้อดีของ IaaS

  1. ไม่จำเป็นต้องซื้อเซิร์ฟเวอร์และอุปกรณ์เครือข่ายทั้งหมดด้วยตนเอง
  2. เลือกและปรับขนาดเครื่องให้สอดคล้องกับความต้องการของระบบได้
  3. สร้างเซิร์ฟเวอร์เสมือนเพื่อพัฒนาและติดตั้งระบบได้รวดเร็ว
  4. เลือกระบบปฏิบัติการ ซอฟต์แวร์ และการตั้งค่าตามขอบเขตบริการ
  5. รองรับตั้งแต่เว็บไซต์ทั่วไปจนถึงระบบองค์กรและงานประมวลผลสูง
  6. เลือกกำลังประมวลผลให้สอดคล้องกับงบประมาณได้

! ข้อเสียของ IaaS

  1. ผู้ใช้อาจต้องดูแลระบบปฏิบัติการ ซอฟต์แวร์ และการอัปเดต
  2. ค่าใช้จ่ายอาจสูงขึ้นหากเปิดทรัพยากรทิ้งไว้หรือเลือกเครื่องใหญ่เกินจำเป็น
  3. ต้องตั้งค่าสิทธิ์ รหัสผ่าน เครือข่าย และการสำรองข้อมูล
  4. ทรัพยากรไม่เพียงพออาจทำให้เว็บไซต์หรือแอปพลิเคชันช้าลง
  5. เซิร์ฟเวอร์เพียงเครื่องเดียวอาจทำให้ระบบหยุดเมื่อเกิดปัญหา จึงควรวางแผนสำรองตามความสำคัญของงาน
📦

2. CaaS — Container as a Service

คอนเทนเนอร์ในรูปแบบบริการ

ความหมายของ CaaS

Container as a Service (CaaS) เป็นบริการคลาวด์ที่ช่วยให้ผู้ใช้สร้าง ปรับใช้ จัดการ และขยายแอปพลิเคชันที่ทำงานภายในคอนเทนเนอร์ผ่านระบบคลาวด์ โดยผู้ให้บริการจัดเตรียมเครื่องมือและทรัพยากรที่จำเป็นสำหรับการทำงานของคอนเทนเนอร์

คอนเทนเนอร์ (Container) เป็นเทคโนโลยีที่ใช้บรรจุแอปพลิเคชัน ไลบรารี และส่วนประกอบที่จำเป็นไว้ด้วยกัน ทำให้แอปพลิเคชันทำงานในสภาพแวดล้อมที่รองรับได้อย่างสม่ำเสมอ ตัวอย่างเทคโนโลยีที่เกี่ยวข้อง ได้แก่ Docker และ Kubernetes

CaaS ช่วยลดภาระในการจัดการระบบคอนเทนเนอร์ ทำให้ติดตั้งแอปพลิเคชันสะดวก เพิ่มความยืดหยุ่นในการจัดสรรทรัพยากร และรองรับการขยายระบบตามปริมาณการใช้งาน อย่างไรก็ตาม ผู้ใช้ยังต้องรับผิดชอบการตั้งค่าแอปพลิเคชัน ข้อมูล และความปลอดภัยตามขอบเขตบริการ

ภาพประกอบแนวคิดบริการคอนเทนเนอร์ของ Alibaba Cloud

CaaS ของ Alibaba Cloud

01 · Container Compute Service (ACS)

บริการประมวลผลคอนเทนเนอร์ที่รองรับ Kubernetes ในรูปแบบ Serverless ช่วยให้เรียกใช้ทรัพยากรประมวลผลสำหรับ Pod โดยไม่จำเป็นต้องบริหารจัดการโหนดพื้นฐานด้วยตนเอง เหมาะกับเว็บแอปพลิเคชัน ไมโครเซอร์วิส และงานที่มีปริมาณเปลี่ยนแปลง

02 · Container Service for Kubernetes (ACK)

บริการจัดการคลัสเตอร์ Kubernetes ช่วยติดตั้ง ปรับใช้ จัดการ และขยายแอปพลิเคชันในคอนเทนเนอร์ เหมาะกับองค์กรที่ต้องบริหารแอปพลิเคชันหลายส่วนหรือหลายบริการร่วมกัน

ความแตกต่าง: ACS มุ่งเน้นการใช้ทรัพยากรประมวลผลคอนเทนเนอร์โดยลดภาระจัดการโครงสร้างพื้นฐาน ส่วน ACK มุ่งเน้นการจัดการคลัสเตอร์ Kubernetes ซึ่งมีแนวทางบริหารโครงสร้างพื้นฐานให้เลือกตามรูปแบบบริการ

✓ ข้อดีของ CaaS

  1. บริการที่มีการจัดการช่วยลดงานดูแลคอนเทนเนอร์และโหนด โดยเฉพาะแบบ Serverless
  2. เพิ่มหรือลดทรัพยากรตามความต้องการของแอปพลิเคชัน
  3. ช่วยให้โปรแกรมทำงานสม่ำเสมอในสภาพแวดล้อมที่รองรับ
  4. แบ่งแอปพลิเคชันเป็นบริการย่อยและปรับปรุงแต่ละส่วนได้
  5. เหมาะกับเว็บไซต์ ไมโครเซอร์วิส และงานประมวลผลข้อมูล
  6. กำหนดทรัพยากรให้เหมาะกับแต่ละแอปพลิเคชันได้
  7. เชื่อมต่อกับระบบซอร์สโค้ดและ CI/CD เพื่อจัดระเบียบการทดสอบและเผยแพร่โปรแกรม

! ข้อเสียของ CaaS

  1. ต้องมีความเข้าใจเรื่องคอนเทนเนอร์ Kubernetes และการแก้ปัญหา
  2. ค่าใช้จ่ายอาจเพิ่มจากการประมวลผล เครือข่าย พื้นที่จัดเก็บ และบริการเสริม
  3. ต้องออกแบบเครือข่าย การเชื่อมต่อ และการจัดเก็บข้อมูลให้เหมาะสม
  4. ต้องคำนึงถึงช่องโหว่ของ Container Image และการกำหนดสิทธิ์
  5. CPU หรือหน่วยความจำไม่พออาจทำให้แอปช้าหรือหยุดทำงาน
  6. การใช้บริการเฉพาะของผู้ให้บริการอาจทำให้ย้ายคลาวด์ซับซ้อนขึ้น

3. PaaS — Platform as a Service

แพลตฟอร์มในรูปแบบบริการ

ความหมายของ PaaS

PaaS คือบริการคลาวด์ที่ให้ผู้ใช้งานพัฒนา ทดสอบ ติดตั้ง และดูแลแอปพลิเคชันผ่านแพลตฟอร์มที่ผู้ให้บริการจัดเตรียมไว้ โดยไม่จำเป็นต้องจัดการโครงสร้างพื้นฐานทั้งหมดด้วยตนเอง เช่น เซิร์ฟเวอร์จริง ระบบปฏิบัติการ และการตั้งค่าระบบพื้นฐานบางส่วน

PaaS เหมาะสำหรับนักพัฒนาเว็บไซต์ นักพัฒนาแอปพลิเคชัน และองค์กรที่ต้องการลดความซับซ้อนในการดูแลระบบ เพื่อให้มุ่งเน้นการเขียนโปรแกรมและพัฒนาฟังก์ชันได้มากขึ้น ตัวอย่างเช่น เว็บไซต์ขายสินค้าออนไลน์สามารถใช้ PaaS เพื่อนำแอปขึ้นใช้งาน จัดการสภาพแวดล้อม และรองรับการปรับขนาดตามจำนวนผู้ใช้ โดยไม่ต้องดูแลเซิร์ฟเวอร์ทุกส่วนเอง

บริการที่เกี่ยวข้องกับ Alibaba Cloud

Serverless App Engine (SAE)

แพลตฟอร์มสำหรับติดตั้งและบริหารจัดการแอปพลิเคชัน ช่วยลดภาระจัดการโครงสร้างพื้นฐาน สามารถกำหนดการปรับขนาดทรัพยากรตามความต้องการ เหมาะกับเว็บแอปและระบบไมโครเซอร์วิส

Function Compute (FC)

บริการประมวลผลแบบ Serverless ที่เรียกใช้โค้ดเมื่อเกิดเหตุการณ์หรือคำขอ โดยไม่ต้องบริหารเซิร์ฟเวอร์โดยตรง โดยทั่วไป FC จัดอยู่ในกลุ่ม FaaS แต่เกี่ยวข้องกับแนวทางพัฒนาแอปพลิเคชันบนคลาวด์ด้วย

✓ ข้อดีของ PaaS

  1. ไม่ต้องจัดการโครงสร้างพื้นฐานทุกส่วนเอง
  2. ใช้แพลตฟอร์มและเครื่องมือที่เตรียมไว้แล้ว
  3. ปรับจำนวนอินสแตนซ์ตามปริมาณใช้งานได้ในบริการที่รองรับ
  4. มีเครื่องมือตรวจสอบและติดตามแอปพลิเคชัน
  5. ไม่จำเป็นต้องซื้อเซิร์ฟเวอร์จริง
  6. เชื่อมต่อเครื่องมือส่งโค้ดและติดตั้งเวอร์ชันใหม่ได้

! ข้อเสียของ PaaS

  1. ปรับแต่งทุกส่วนได้ไม่อิสระเท่าการดูแลเซิร์ฟเวอร์เอง
  2. ต้องติดตามต้นทุนทรัพยากร บริการเสริม และการรับส่งข้อมูล
  3. ต้องเข้าใจการตั้งค่าและขั้นตอนนำแอปขึ้นใช้งาน
  4. พึ่งพาเครื่องมือเฉพาะแพลตฟอร์มอาจทำให้ย้ายระบบยากขึ้น
  5. ผู้ใช้ยังต้องดูแลสิทธิ์ ข้อมูล และการตั้งค่าของแอปพลิเคชัน
  6. ข้อจำกัดด้านภาษา เครื่องมือ หรือรูปแบบติดตั้งอาจไม่เหมาะกับบางระบบ
⚡

4. FaaS — Function as a Service

ฟังก์ชันในรูปแบบบริการ

ความหมายของ FaaS

FaaS เป็นรูปแบบหนึ่งของ Cloud Computing ที่ช่วยให้นักพัฒนาเขียนและเรียกใช้โค้ดเป็นฟังก์ชันย่อย ๆ โดยไม่จำเป็นต้องจัดการเซิร์ฟเวอร์ด้วยตนเอง ผู้ให้บริการคลาวด์ดูแลโครงสร้างพื้นฐานและจัดสรรทรัพยากรสำหรับประมวลผลตามการทำงานของฟังก์ชัน

FaaS มักทำงานร่วมกับแนวคิด Serverless Computing ซึ่งไม่ได้หมายความว่าไม่มีเซิร์ฟเวอร์อยู่จริง แต่หมายถึงผู้ใช้ไม่ต้องบริหารจัดการเซิร์ฟเวอร์โดยตรง ฟังก์ชันสามารถทำงานเมื่อมีเหตุการณ์หรือคำขอ เช่น การอัปโหลดไฟล์ การส่งคำสั่งซื้อ หรือการเรียก API

ตัวอย่างการใช้งาน: เว็บไซต์ขายสินค้าออนไลน์สามารถเรียกฟังก์ชันส่งอีเมลยืนยันคำสั่งซื้อเมื่อระบบได้รับเหตุการณ์ว่าลูกค้าชำระเงินสำเร็จ แทนการเปิดเซิร์ฟเวอร์แยกเพื่อทำงานนี้ตลอดเวลา

บริการ FaaS ของ Alibaba Cloud: Function Compute (FC)

Function Compute เป็นบริการประมวลผลแบบ Serverless ของ Alibaba Cloud ที่ช่วยให้ผู้ใช้พัฒนาและเรียกใช้โค้ดตามเหตุการณ์หรือคำขอ โดยไม่ต้องดูแลเซิร์ฟเวอร์พื้นฐานด้วยตนเอง รองรับงานที่เกี่ยวข้องกับ API การประมวลผลข้อมูล และการตอบสนองต่อเหตุการณ์จากบริการอื่น

✓ ข้อดีของ FaaS

  1. ผู้ให้บริการจัดการโครงสร้างพื้นฐานสำหรับประมวลผล
  2. คิดค่าบริการตามการใช้งานในรูปแบบที่บริการกำหนด หากไม่มีการใช้ทรัพยากรประมวลผลอาจไม่มีค่าใช้จ่ายส่วนนั้น แต่ต้องตรวจสอบค่าใช้จ่ายอื่น
  3. เพิ่มหรือลดทรัพยากรตามภาระงานภายในขีดจำกัดบริการ
  4. นักพัฒนามุ่งเน้นการเขียนโค้ดแก้ปัญหาทางธุรกิจ
  5. ตั้งให้ฟังก์ชันทำงานเมื่อเกิดเหตุการณ์ตามเงื่อนไข
  6. ใช้กับ API การประมวลผลไฟล์ วิดีโอ ข้อมูล และ AI ได้

! ข้อเสียของ FaaS

  1. บางกรณีต้องเตรียมอินสแตนซ์ก่อน จึงเพิ่มเวลาตอบสนองได้
  2. มีข้อกำหนดด้านเวลา หน่วยความจำ และการประมวลผล
  3. เมื่อมีฟังก์ชันจำนวนมาก การติดตามปัญหาข้ามบริการอาจยาก
  4. การใช้บริการเฉพาะคลาวด์อาจทำให้ย้ายผู้ให้บริการซับซ้อน
  5. การเรียกบ่อย ใช้ทรัพยากรสูง หรือรับส่งข้อมูลมาก อาจทำให้ค่าใช้จ่ายสูง
  6. งานที่ต้องทำต่อเนื่องนานหรือมีสถานะซับซ้อนอาจต้องใช้บริการอื่นร่วมด้วย

5. DaaS — Database as a Service

ฐานข้อมูลในรูปแบบบริการ

ความหมายของ DaaS

Database as a Service (DaaS) ในบริบทนี้หมายถึงบริการฐานข้อมูลผ่านระบบคลาวด์ ผู้ใช้งานสามารถสร้าง จัดเก็บ ประมวลผล และจัดการข้อมูลผ่านอินเทอร์เน็ต โดยไม่จำเป็นต้องลงทุนติดตั้งเซิร์ฟเวอร์ฐานข้อมูลและดูแลโครงสร้างพื้นฐานทั้งหมดด้วยตนเอง ผู้ให้บริการรับผิดชอบการจัดการทรัพยากรและสนับสนุนการบำรุงรักษาตามขอบเขตบริการที่เลือกใช้

Alibaba Cloud มีบริการฐานข้อมูลหลายประเภท รองรับตั้งแต่การจัดเก็บข้อมูลทั่วไป การประมวลผลธุรกรรม ไปจนถึงการวิเคราะห์ข้อมูลขนาดใหญ่ โดยมีผลิตภัณฑ์สำคัญ ได้แก่ ApsaraDB RDS, PolarDB และ AnalyticDB

บริการ DaaS ของ Alibaba Cloud

01 · ApsaraDB RDS

บริการฐานข้อมูลเชิงสัมพันธ์บนคลาวด์ รองรับระบบฐานข้อมูลหลายชนิด เช่น MySQL, PostgreSQL, SQL Server และ MariaDB ตามผลิตภัณฑ์และรุ่นที่ให้บริการ ข้อมูลจัดเก็บในรูปแบบตารางที่เชื่อมโยงกันได้ เหมาะกับเว็บไซต์ ระบบซื้อขายสินค้า ระบบสมาชิก และระบบองค์กร มีเครื่องมือสนับสนุนการสำรองและกู้คืนข้อมูล การตรวจสอบประสิทธิภาพ และความพร้อมใช้งาน

02 · PolarDB

บริการฐานข้อมูลบนคลาวด์ที่ออกแบบมาสำหรับงานประสิทธิภาพสูงและการขยายระบบตามปริมาณการใช้งาน รองรับรูปแบบที่เข้ากันได้กับ MySQL, PostgreSQL หรือ Oracle ตามรุ่นผลิตภัณฑ์ เหมาะกับธุรกิจที่มีข้อมูลมากและแอปพลิเคชันที่ต้องประมวลผลต่อเนื่อง

03 · AnalyticDB

บริการฐานข้อมูลที่เน้นการวิเคราะห์ข้อมูลขนาดใหญ่และการประมวลผลเพื่อสนับสนุนการตัดสินใจ เช่น วิเคราะห์ยอดขาย พฤติกรรมลูกค้า สร้างรายงาน และประมวลผลข้อมูลจากหลายแหล่ง

หลักการทำงานของ DaaS

ผู้ใช้งานหรือแอปพลิเคชันส่งคำสั่งไปยังฐานข้อมูลบนคลาวด์ ระบบตรวจสอบคำสั่งและประมวลผล เช่น เพิ่มสินค้า แก้ไขข้อมูลลูกค้า ค้นหารายการสั่งซื้อ หรือลบข้อมูลที่ไม่จำเป็น จากนั้นส่งผลลัพธ์กลับไปยังแอปพลิเคชัน ฝั่งผู้ให้บริการมีเครื่องมือจัดการทรัพยากร ตรวจสอบประสิทธิภาพ สำรองข้อมูล และรักษาความปลอดภัยตามคุณสมบัติของบริการ

✓ ข้อดีของ DaaS

  1. ลดความจำเป็นในการซื้อและติดตั้งเซิร์ฟเวอร์ฐานข้อมูล
  2. ปรับขนาดทรัพยากรตามจำนวนผู้ใช้และปริมาณข้อมูลได้
  3. ผู้ให้บริการรับผิดชอบโครงสร้างพื้นฐานและการบำรุงรักษาหลายส่วน
  4. มีเครื่องมือควบคุมสิทธิ์ เข้ารหัส และจัดการเครือข่ายตามบริการ
  5. ช่วยลดความเสี่ยงข้อมูลสูญหายเมื่อกำหนดนโยบายสำรองเหมาะสม
  6. นำข้อมูลไปทำรายงาน วิเคราะห์แนวโน้ม และช่วยตัดสินใจได้
  7. ใช้กับเว็บไซต์ แอปมือถือ ระบบซื้อขาย และระบบองค์กร

! ข้อเสียของ DaaS

  1. ต้องเชื่อมต่อเครือข่ายเพื่อเข้าถึงบริการ และค่าใช้จ่ายอาจเพิ่มตามทรัพยากร พื้นที่จัดเก็บ และปริมาณใช้งาน
  2. ต้องกำหนดสิทธิ์และมาตรการความปลอดภัยให้เหมาะสม
  3. การพึ่งพาเทคโนโลยีของผู้ให้บริการมากเกินไปอาจทำให้ย้ายฐานข้อมูลยาก ใช้เวลา และมีค่าใช้จ่ายเพิ่ม
🛡️

6. Security & Identity

ความปลอดภัยและการจัดการตัวตนดิจิทัล

แนวคิด Zero Trust และการรักษาความปลอดภัยดิจิทัล

Alibaba Cloud ให้ความสำคัญกับการรักษาความปลอดภัยของระบบคลาวด์ โดยสามารถประยุกต์ใช้แนวคิดสถาปัตยกรรมแบบ Zero Trust ซึ่งยึดหลักว่าไม่ควรเชื่อถือผู้ใช้งานหรืออุปกรณ์ใดโดยอัตโนมัติ ไม่ว่าจะเชื่อมต่อจากภายในหรือภายนอกเครือข่าย ทุกการเข้าถึงทรัพยากรจึงต้องผ่านการตรวจสอบตัวตนและสิทธิ์ที่เหมาะสม

แนวทางดังกล่าวให้ความสำคัญกับการจัดการตัวตนดิจิทัล (Digital Identity) การกำหนดสิทธิ์ (Authorization) การตรวจสอบกิจกรรม (Audit) การยืนยันตัวตน (Authentication) และการควบคุมการใช้งานแอปพลิเคชัน ควบคู่กับการจัดการคีย์ความปลอดภัย เพื่อจำกัดขอบเขตความเสียหายจากการเข้าถึงโดยไม่ได้รับอนุญาต

โครงสร้างและบริการหลักด้าน IDaaS

Identity as a Service (IDaaS) เป็นบริการสำหรับจัดการตัวตนและสิทธิ์การเข้าถึงในรูปแบบคลาวด์ ช่วยให้องค์กรบริหารบัญชีผู้ใช้จากส่วนกลาง ลดความซ้ำซ้อน และควบคุมสิทธิ์การใช้งานระบบต่าง ๆ ได้สะดวก

Enterprise IAM (EIAM)

บริการจัดการตัวตนและสิทธิ์การเข้าถึงสำหรับองค์กร ช่วยให้พนักงานเข้าสู่ระบบแอปพลิเคชันหลายรายการผ่าน Single Sign-On (SSO) และรองรับมาตรฐาน เช่น SAML 2.0, OpenID Connect (OIDC) และ OAuth 2.0 สามารถประยุกต์ใช้ Multi-Factor Authentication (MFA) เพื่อเพิ่มความปลอดภัย

User Directory & Provisioning

กลไกจัดเก็บและบริหารบัญชีจากส่วนกลาง รวมถึงการสร้าง ปรับปรุง และยกเลิกสิทธิ์ตามสถานะบุคลากร เช่น รับพนักงานใหม่ เปลี่ยนแผนก หรือสิ้นสุดการจ้างงาน เพื่อลดความเสี่ยงจากบัญชีที่ยังมีสิทธิ์เกินจำเป็น

Privileged Access Management (PAM)

แนวทางควบคุมบัญชีสิทธิ์สูง เช่น บัญชีผู้ดูแลระบบ โดยจำกัดสิทธิ์และระยะเวลาเท่าที่จำเป็น การให้สิทธิ์ชั่วคราวตามการใช้งานจริง (Just-in-Time Access: JIT) ช่วยลดความเสี่ยงจากการเก็บข้อมูลรับรองสิทธิ์สูงไว้ถาวร

ตัวตนของ AI Agents

ควบคุมสิทธิ์ของตัวตนที่ไม่ใช่มนุษย์ เช่น โปรแกรมอัตโนมัติและ AI Agents ให้เหมาะกับภารกิจ รวมถึงจัดเก็บและปกป้อง API Keys ผ่านระบบจัดการกุญแจเข้ารหัส เช่น Key Management Service (KMS)

ข้อควรตรวจสอบ: ชื่อผลิตภัณฑ์ ความพร้อมใช้งาน และรายละเอียดฟังก์ชันด้าน IAM/PAM อาจแตกต่างกันตามภูมิภาคและรุ่นบริการ ควรตรวจสอบเอกสารทางการของ Alibaba Cloud ก่อนนำไปใช้งานจริง
📊

ตารางเปรียบเทียบบริการคลาวด์

สรุปความแตกต่างเพื่อช่วยเลือกบริการให้เหมาะกับงาน

รูปแบบสิ่งที่ให้บริการหลักผู้ใช้ดูแลอะไรเป็นหลักตัวอย่าง Alibaba Cloud
IaaSเซิร์ฟเวอร์เสมือน เครือข่าย และพื้นที่จัดเก็บระบบปฏิบัติการ ซอฟต์แวร์ และการตั้งค่าระบบECS
CaaSการรันและจัดการคอนเทนเนอร์คอนเทนเนอร์ แอปพลิเคชัน การตั้งค่าและความปลอดภัยตามบริการACS, ACK
PaaSแพลตฟอร์มสำหรับพัฒนาและติดตั้งแอปโค้ด ข้อมูล และการตั้งค่าของแอปSAE (และบริการแพลตฟอร์มที่เกี่ยวข้อง)
FaaSเรียกใช้ฟังก์ชันตามเหตุการณ์หรือคำขอโค้ด ฟังก์ชัน เหตุการณ์ และสิทธิ์การเข้าถึงFunction Compute (FC)
DaaSฐานข้อมูลบนคลาวด์ข้อมูล การเข้าถึง การออกแบบและการใช้งานฐานข้อมูลApsaraDB RDS, PolarDB, AnalyticDB
IDaaS / Identityตัวตนดิจิทัลและสิทธิ์การเข้าถึงนโยบายบัญชี สิทธิ์ และการตรวจสอบการใช้งานบริการ IAM/Identity ตามผลิตภัณฑ์ที่เปิดให้ใช้

หมายเหตุ: ขอบเขตความรับผิดชอบและการจัดประเภทบริการอาจแตกต่างกันตามผลิตภัณฑ์ รุ่น และรูปแบบการตั้งค่า ควรอ้างอิงเอกสารทางการเมื่อใช้งานจริง
